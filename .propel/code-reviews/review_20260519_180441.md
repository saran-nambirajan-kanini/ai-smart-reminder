## Findings

### MEDIUM

#### M1: Placeholder credentials in appsettings.json committed to source control

**File:** `src/AiSmartReminder.Api/appsettings.json` L10-16
**Category:** Security (OWASP A05 - Security Misconfiguration)

```json
"ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=aismartreminder;Username=postgres;Password=CHANGE_ME"
},
"JwtSettings": {
    "Secret": "CHANGE_ME_USE_A_SECURE_SECRET_OF_AT_LEAST_32_CHARS",
```

**Issue:** While clearly marked as placeholders, these values are committed to source control. If developers forget to override them via environment variables or user-secrets in non-development environments, they could be deployed to production.

**Recommendation:** Add a `.gitignore` entry for `appsettings.*.local.json` and use `dotnet user-secrets` for local development. Consider making `appsettings.json` contain only non-sensitive defaults and require environment variables for sensitive values.

**Risk:** Low in practice (startup validation will catch missing/invalid values), but best practice is to avoid any credential-like strings in source control.

---

#### M2: No global exception handling middleware

**File:** `src/AiSmartReminder.Api/Program.cs`
**Category:** Error Handling / Security (OWASP A09 - Security Logging and Monitoring Failures)

**Issue:** The middleware pipeline does not include `app.UseExceptionHandler()` for production environments. Without this, unhandled exceptions may expose stack traces and internal details to API consumers.

**Recommendation:** Add exception handling middleware:
```csharp
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}
else
{
    app.UseExceptionHandler("/error");
}
```

**Risk:** Medium — in production, unhandled exceptions would return default 500 responses with potentially sensitive error details.

### LOW

#### L1: FluentAssertions 8.x commercial license requirement

**File:** `tests/AiSmartReminder.Architecture.Tests/AiSmartReminder.Architecture.Tests.csproj` L14
**Category:** Licensing

**Issue:** FluentAssertions 8.x introduced a commercial license requirement (Xceed License Agreement). The test output shows a license warning. For commercial projects, a paid subscription is required.

**Recommendation:** Either acquire a commercial license or downgrade to FluentAssertions 6.x (MIT licensed), or switch to `Shouldly` or built-in xUnit assertions.

---

#### L2: CORS allows AllowAnyHeader and AllowAnyMethod

**File:** `src/AiSmartReminder.Api/Program.cs` L25-26
**Category:** Security (OWASP A05 - Security Misconfiguration)

```csharp
policy.WithOrigins(allowedOrigins)
      .AllowAnyHeader()
      .AllowAnyMethod();
```

**Issue:** While origins are restricted, allowing any header and any method is overly permissive for production. This is acceptable for early development but should be tightened before production deployment.

**Recommendation:** Restrict to specific headers (`Content-Type`, `Authorization`) and methods (`GET`, `POST`, `PUT`, `DELETE`) in production configuration.

---

#### L3: Health check has no custom checks registered

**File:** `src/AiSmartReminder.Api/Program.cs` L17
**Category:** Observability

```csharp
builder.Services.AddHealthChecks();
```

**Issue:** The health check only reports "Healthy" without checking actual dependencies (database, external services). This provides limited operational value.

**Recommendation:** This is acceptable for the current scaffolding phase. When database and external services are added (future tasks), register dependency health checks (e.g., `AddNpgSql()`, custom checks for AI services).
